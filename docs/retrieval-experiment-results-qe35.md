# 検索層実験 追試 — QE モデルを gemini-3.5-flash-lite に差し替え

実行日: 2026-07-21（本試験 [retrieval-experiment-results.md](retrieval-experiment-results.md) の直後）
狙い: query expansion（QE）の LLM を **`gemini-3.1-flash-lite` → `gemini-3.5-flash-lite`（新リリース）** に替えると検索が良くなるか。
eval set / k / Base は本試験と同一（`eval_set_merged.json` 66問, k=5, Base=structure dense-only）。

> **これは本試験（3.1）とは別成果物**。CSV も別ファイル、本ドキュメントも別。3.1 の結果は一切上書きしていない。

---

## 0. 結論（先に）

- **QE を 3.5-flash-lite にしても改善しない。むしろ全指標で 3.1 より悪化（有意ではないが一貫して負）。**
- 本試験で唯一の希望だった **条件C recall の「ニアミス」信号（3.1 で vs Base p=0.099）が、3.5 では消えた**（vs Base p=0.49）。新しいモデルが唯一の勾配を潰した。
- **採否判断: QE は 3.1-flash-lite のまま。3.5-flash-lite への差し替えは不採用。** 「新しい＝この用途で良い」は成り立たなかった。
- 生成層（回答生成）の話ではない点に注意。ここで替えたのは**検索前の QE 1 回**だけ。検索実験なので生成モデルは無関係。

---

## 1. やったこと（最小差分）

- `QE_MODEL` を env 分離（`os.getenv("QE_MODEL", config.GEMINI_MODEL)`）。config.GEMINI_MODEL は RAGAS judge 兼用なので、QE だけ切り替えられるようにした。
- **cache と出力ファイルをモデル別に**（`qe_cache_{model}.json` / `scores_condition_{name}_{model}_{date}.{json,csv}`）。3.1 の cache を読まず、3.1 の成果物を上書きしないため。
- **A（dense+sparse, QEなし）は再実行していない**。QE を使わないので 3.1/3.5 で結果は不変。回すのは B・C のみ（RPD 節約）。
- モデル id は実在確認してから回した（1問 smoke test で 1.1s 正常応答。CLAUDE.md「API 挙動は必ず検証」）。

## 2. 集計（3.1 と並べて）

| 条件 | QE model | recall@5 | strict_hit | MRR | AND (n=27) | single (n=20) |
| --- | --- | --- | --- | --- | --- | --- |
| Base | — | 0.599 | 0.500 | 0.562 | 0.352 | 0.850 |
| B | 3.1-flash-lite | 0.636 | 0.500 | 0.614 | 0.407 | 0.900 |
| **B** | **3.5-flash-lite** | **0.611** | 0.500 | 0.562 | 0.383 | 0.850 |
| C | 3.1-flash-lite | **0.674** | 0.545 | 0.615 | 0.426 | **1.000** |

- B・C とも recall/MRR/single が 3.1 → 3.5 で下がった。AND は C で同値（0.426）、B で微減。
- 特に **C の single が 1.000 → 0.850** に落ちた（3.1 の目玉だった全問正解が崩れた）。

## 3. paired difference（本命の判断材料）

### 3.5 QE vs Base（同一66問）

| 比較 | 指標 | 平均差 | 95%CI | 改善/悪化/不変 | p |
| --- | --- | --- | --- | --- | --- |
| Base→B(3.5) | recall | +0.013 | [−0.040, +0.066] | 4/2/60 | 0.97 |
| Base→C(3.5) | recall | +0.030 | [−0.043, +0.106] | 7/4/55 | 0.49 |

→ どちらも 3.1 のとき（B +0.038 / **C +0.076, p=0.099**）より弱い。**C の near-miss 信号が消えた。**

### モデル入替 3.1 → 3.5（同条件・同一66問で直接比較）

| 比較 | 指標 | 平均差 (3.5−3.1) | 95%CI | 改善/悪化/不変 | p |
| --- | --- | --- | --- | --- | --- |
| B: 3.1→3.5 | recall | **−0.025** | [−0.083, +0.030] | 2/5/59 | 0.52 |
| B: 3.1→3.5 | mrr | **−0.052** | [−0.122, +0.010] | 8/12/46 | 0.17 |
| C: 3.1→3.5 | recall | **−0.045** | [−0.121, +0.023] | 3/6/57 | 0.28 |
| C: 3.1→3.5 | mrr | **−0.030** | [−0.089, +0.030] | 9/15/42 | 0.34 |

→ **4比較すべて符号が負**（悪化）。CI は全部 0 をまたぐので「有意に悪い」とまでは言えないが、**改善方向の証拠はゼロ**。悪化件数が改善件数を一貫して上回る（C recall 3改善/6悪化, B mrr 8/12 等）。

## 4. 解釈

- 3.5-flash-lite は 3.1 より新しく・一般には賢いはずだが、**この QE タスク（度数正規化・同義語の短い追記）では優位が出ないどころか一貫して劣後**した。
- 原因の仮説（未検証・TODO）: QE プロンプトは「短い語・フレーズのみ追記」を強く制約している。新モデルが**より饒舌 or 別の語彙選択**をして、コーパス側の語彙から却って離れた可能性。実際、3.5 の展開文は 3.1 より語数が多い傾向（各 CSV の `expanded_query` 列で確認可）。→ **プロンプトはモデルごとにチューニングが要る**という一般則の一例。
- したがって「モデルを上げれば QE が良くなる」は**この設定では偽**。QE の効き方は展開文とコーパス語彙の一致で決まり、モデルの一般知能とは別軸。

---

## 5. 限界（本試験と共通）

- n=66 では全比較 CI が 0 をまたぐ。**「3.5 が有意に悪い」ではなく「良くなる証拠がない」**が正確な言い方。
- notation_variant タグ未付与のため、主指標（表記ゆれ層 recall）では評価していない。全66問平均の近似。
- QE 展開はモデル確率的だが、cache 固定なので本 run 内は再現的。3.1 と 3.5 は別 cache（別展開文）。

---

## 6. 判断と次の一手

- **QE モデルは 3.1-flash-lite を継続。3.5-flash-lite は不採用。**
- どうしても 3.5 を活かすなら、**QE プロンプトを 3.5 向けに再設計**して（より厳しく「単語のみ・N語以内」制約）から測り直す。ただし本試験の主眼（sparse/QE の要因分離）からは外れる寄り道。
- 本筋の次手は本試験 §7 と同じ: **notation_variant タグ付与 → C(3.1) recall を表記ゆれ層で撃ち直す**、その後 RAGAS。
